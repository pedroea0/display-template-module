# Display Template events

The Display Template fires four component events. Configure them like any Perspective component event: right-click the
component > **Configure Events...**, pick the event under *Component Events*, and add a Script, Popup or Navigate
action.

**On this page**

- [Overview](#overview)
- [Events are not proof](#events-are-not-proof)
- [onSetpointWrite](#onsetpointwrite)
- [onTagConfigEdit](#ontagconfigedit)
- [onTrendChange](#ontrendchange)
- [onMenuAction](#onmenuaction)

---

## Overview

| Event | Fired by | When |
|---|---|---|
| `onSetpointWrite` | gateway | after every write attempt that reached the tag provider (success or failure), **before** the client sees the result |
| `onTagConfigEdit` | gateway | after a **Tag Configuration…** edit attempt (success or failure) |
| `onTrendChange` | gateway | after a successful **Trend Tag** / **Remove from Trend** |
| `onMenuAction` | browser | after a UI-only menu item: `trendPage`, `trendPopup`, `copyPath`, or a custom item |

Script actions read the payload as attributes of `event`: `event.tagPath`, `event.user`, `event.auditId` (verified on
8.3.10). Gateway-fired events do not fire in Designer design mode.

## Events are not proof

> **Important** A user with a browser console can fire any component event with any payload, and the actions attached
> to it run. Never use an event as proof that a write happened, and never let an event script do something the user may
> not do. The **audit profile** is the authoritative record: reconcile with `auditId`, and check that the record matches
> the event (a UUID id from the record's suffix, same tag, user and values), as the
> [setpoint-log sample](../../samples/setpoint-log-script.md#reconciling-with-the-audit-profile) does. A bare
> `valueFilter='%auditId=' + event.auditId + '%'` lookup is not enough: a forged id of `%` matches every record.

## onSetpointWrite

Fires after every setpoint write attempt that **reached the tag provider**, successful or not, before the client gets
the result. Validation refusals (limits, roles, options, step guard) do not fire it, because nothing was sent to the
tag. A write that timed out fires with `success: false`, `errorCode: "TIMEOUT"`; the late outcome is in the
[audit trail](menu-and-setpoints.md#audit-trail-who-changed-what).

<!-- BEGIN GENERATED: events displaytemplate onSetpointWrite -->

Fired on the gateway after every setpoint write attempt that reached the tag (success or failure), before the client gets the result. Like every component event, this payload can be imitated by a page script; the audit log (auditId) is the authoritative record.

| Field | Type | Description |
|---|---|---|
| `tagPath` | string | Full path of the written tag, e.g. [default]Area/Tank1/Level_SP. |
| `value` | any | Value written (after conversion to the tag data type). |
| `previousValue` | any | Tag value read just before the write. |
| `success` | boolean | True when the tag accepted the write (Good quality). |
| `quality` | string | Write result quality name, e.g. Good or Bad_AccessDenied. |
| `errorCode` | string \| null | Error code when success is false (e.g. WRITE_DENIED), else null. |
| `user` | string | User name of the Perspective session, or "Unauthenticated". |
| `timestamp` | number | Gateway time of the write, epoch milliseconds. |
| `editMode` | string | How the value was entered: popup, direct, protected or unknown. |
| `auditId` | string | Id of the matching audit record / SimpleTagDisplay.Audit log line. |

<!-- END GENERATED: events displaytemplate onSetpointWrite -->

Example: log every failed write.

```python
def runAction(self, event):
    if not event.success:
        system.util.getLogger('Setpoints').warn(
            '%s could not write %s = %s (%s, auditId %s)' % (
                event.user, event.tagPath, event.value, event.errorCode, event.auditId))
```

A full sample that stores writes in a database table and reconciles them with the audit profile:
[samples/setpoint-log-script.md](../../samples/setpoint-log-script.md).

## onTagConfigEdit

Fires after an attempt to change the tag's Engineering Units, Low or High limit through **Tag Configuration…**
(success or failure), before the client gets the result. Fields that were not changed are `null`.

<!-- BEGIN GENERATED: events displaytemplate onTagConfigEdit -->
<!-- Generated by simple-tag-display/tools/gen-prop-docs.mjs from the schemas. Do not edit by hand. -->

Fired on the gateway after an attempt to change the tag's units or engineering limits (success or failure), before the client gets the result. Like every component event, this payload can be imitated by a page script; the audit log (auditId) is the authoritative record.

| Field | Type | Description |
|---|---|---|
| `tagPath` | string | Full path of the edited tag. |
| `engUnit` | string \| null | New Engineering Units (null = not changed). |
| `engLow` | number \| null | New Engineering Low Limit (null = not changed). |
| `engHigh` | number \| null | New Engineering High Limit (null = not changed). |
| `previousEngUnit` | string \| null | Engineering Units before the edit. |
| `previousEngLow` | number \| null | Engineering Low Limit before the edit. |
| `previousEngHigh` | number \| null | Engineering High Limit before the edit. |
| `success` | boolean | True when the tag configuration was saved. |
| `quality` | string | Save result quality name. |
| `errorCode` | string \| null | Error code when success is false, else null. |
| `user` | string | User name of the Perspective session. |
| `timestamp` | number | Gateway time of the edit, epoch milliseconds. |
| `auditId` | string | Id of the matching audit record / SimpleTagDisplay.Audit log line. |

<!-- END GENERATED: events displaytemplate onTagConfigEdit -->

Example: tell the engineering team.

```python
def runAction(self, event):
    if event.success:
        system.util.getLogger('TagConfig').info('%s changed %s: low %s -> %s, high %s -> %s' % (
            event.user, event.tagPath, event.previousEngLow, event.engLow, event.previousEngHigh, event.engHigh))
```

## onTrendChange

Fires after the tag was added to or removed from the session trend list of `trendGroup` (from this display's menu).

<!-- BEGIN GENERATED: events displaytemplate onTrendChange -->
<!-- Generated by simple-tag-display/tools/gen-prop-docs.mjs from the schemas. Do not edit by hand. -->

Fired on the gateway after the tag was added to or removed from the session trend list. Like every component event, this payload can be imitated by a page script; the audit log (auditId) is the authoritative record.

| Field | Type | Description |
|---|---|---|
| `action` | string | "add" or "remove". |
| `tagPath` | string | Full path of the tag. |
| `group` | string | Trend group (trendGroup) that changed. |
| `user` | string | User name of the Perspective session. |
| `timestamp` | number | Gateway time, epoch milliseconds. |

<!-- END GENERATED: events displaytemplate onTrendChange -->

Example: open the trend page the first time a tag is added.

```python
def runAction(self, event):
    if event.action == 'add':
        system.perspective.navigate('/trend')
```

## onMenuAction

Fires in the browser when the operator picks a menu item that has no gateway action: **Go to Trend Page**, **Open Trend
Popup**, **Copy Tag Path**, or one of your `menu.items`. `action` is the item's id. The built-in items still do their
own job (navigate, open the popup, copy); the event lets you add to it. Custom items do nothing else, so attach your
action here.

<!-- BEGIN GENERATED: events displaytemplate onMenuAction -->
<!-- Generated by simple-tag-display/tools/gen-prop-docs.mjs from the schemas. Do not edit by hand. -->

Fired in the browser when a menu item is chosen (custom items, trend page / popup items). Attach Popup, Navigate or Script actions here. Like every component event, this payload can be imitated by a page script; the audit log (auditId) is the authoritative record.

| Field | Type | Description |
|---|---|---|
| `action` | string | Id of the chosen item (custom item id, or trendPage / trendPopup / copyPath). |
| `tagPath` | string | Full path of the tag shown by the component. |
| `tagName` | string | Tag name (last part of tagPath). |
| `trendGroup` | string | Trend group of the component. |

<!-- END GENERATED: events displaytemplate onMenuAction -->

Example: a custom *Details…* item (`menu.items: [{ "id": "details", "label": "Details…" }]`).

```python
def runAction(self, event):
    if event.action == 'details':
        system.perspective.openPopup('details', 'Popups/Details', params={'tagPath': event.tagPath})
```
