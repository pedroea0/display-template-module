# Display Template properties

Every prop of the Display Template, grouped the way the Designer's property editor shows them. Each group starts with
a short explanation and an example; the table under it lists **every** path in the group.

**How to read the tables**

| Column | Meaning |
|---|---|
| Prop | the path in the property tree; `setpoint.access.roles` is `roles` inside `access` inside `setpoint`, and `[]` marks the items of an array (`states.options[].label`) |
| Type | the JSON type; `string (colour)` takes any CSS colour, `style` is a Perspective style object (inline styles plus `classes`) |
| Default | the value a new component starts with; an empty cell on an object means "see its children" |
| Description | what it does, followed by the valid values (`One of …`, ranges, lengths) |

**[S]** marks a **security prop**: the gateway reads it from its own trusted copy and enforces it, so a change made in
the browser is put back and logged. Configure security props statically (or bind them only to trusted sources such as
`session.props.auth.*`); see [Trusted props](../../security-and-permissions.md#trusted-props).

The tables are generated from the component's JSON schema (the same descriptions appear in the Designer's property
editor), so they always match the shipped module.

## Tag and behaviour

`tagPath` is the only prop a new display needs. Write it with its provider (`[default]Area1/Tank1/Level`); a path
without a provider uses the project's default provider. It must point at a tag, not at a property (`.EngUnit`) or an
alarm. `tagPath` may be bound to a view parameter (a faceplate), exactly like a tag binding.

`enabled: false` keeps the value live but turns every interaction off (menu, editing, trending). To control **who** may
edit, use `setpoint.enabled` and `setpoint.access` instead.

`trendGroup` names the session trend list that **Trend Tag** adds to; charts with the same group show it
([Trend groups](menu-and-setpoints.md#trend-groups)).

```json
"tagPath": "[default]Area1/Tank1/Level",
"trendGroup": "area1"
```

## Value

How the value is formatted. For numbers, the first of these wins: `value.decimals`, `value.format`, the tag's Format
String, `#,##0.##`. Formatting follows the session locale. More: [Showing the value](README.md#showing-the-value).

```json
"value": { "format": "#,##0.0", "style": { "fontWeight": "bold" } }
```

## States

```json
  "boolean": { "trueText": "Running", "falseText": "Stopped" },

  "unmatchedText": "Unknown"
```

Engineering Low/High. Recipe: [Bounds from another tag](recipes.md#bounds-from-another-tag-or-from-alarm-limits).

```json
"bounds": { "enabled": true, "lowAlarmName": "Lo", "highAlarmName": "Hi" }
```

## Setpoint

Lets the operator write a new value. The **[S]** props here are the write gate: the gateway checks each of them, plus
the gateway floor policy and the tag's own Write Permissions, before it writes. The others shape the editor (mode,
confirmation, popup). Guide: [Menu and setpoints](menu-and-setpoints.md).

```json
"setpoint": {
  "enabled": true,
  "access": { "roles": ["Operator"] },
  "limits": { "low": 0, "high": 150 },
  "maxStep": 10,
  "mode": "popup",
  "confirm": "always"
}
```

## Layout

Column (label above value) or row (label beside value), alignment, gap, and automatic font sizing. With
`layout.autoFontSize.enabled` the text grows and shrinks with the component; a font size you set in a style always wins.

```json
"layout": { "direction": "row", "evenSplit": true, "autoFontSize": { "enabled": false } }
```
